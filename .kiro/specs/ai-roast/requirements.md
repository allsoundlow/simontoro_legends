# Requirements Document

## Introduction

The AI Roast feature adds a `/roast` command that allows group members to generate playful, AI-powered roasts of other users in the chat. This feature integrates with OpenRouter AI to generate creative, humorous roasts based on user-provided context and configurable intensity levels.

The feature serves as a fun engagement driver for gaming communities while establishing the OpenRouter AI integration pattern for future AI-powered features.

## Glossary

- **Roast**: A playful, humorous insult or teasing comment generated by AI
- **Roast_Level**: The intensity of the roast (soft, hard, extra)
- **OpenRouter**: The AI provider service used for generating roasts
- **Target_User**: The Telegram user being roasted (identified by @mention)
- **Context**: Optional free-form text provided by the user to guide the roast content
- **GenerateRoast_Use_Case**: The use case that orchestrates roast generation
- **OpenRouterClient**: The HTTP client connector for OpenRouter API
- **TelegramRouter**: The declarative command routing system that maps commands to use cases
- **Rate_Limiter**: Component that enforces usage limits per user, group, and globally

## Requirements

### Requirement 1: Command Parsing

**User Story:** As a group member, I want to use a simple command format to roast other users, so that I can quickly generate fun content without complex syntax.

#### Acceptance Criteria

1. WHEN a user sends `/roast @username`, THE Command_Parser SHALL extract the target username and use the default level "hard"
2. WHEN a user sends `/roast @username soft`, THE Command_Parser SHALL extract the target username and set level to "soft"
3. WHEN a user sends `/roast @username hard`, THE Command_Parser SHALL extract the target username and set level to "hard"
4. WHEN a user sends `/roast @username extra`, THE Command_Parser SHALL extract the target username and set level to "extra"
5. WHEN a user sends `/roast @username hard some context here`, THE Command_Parser SHALL extract the target username, level, and context text
6. WHEN a user sends `/roast @username some context without level`, THE Command_Parser SHALL extract the target username, use default level "hard", and capture the remaining text as context
7. THE Command_Parser SHALL treat roast level keywords as case-insensitive (SOFT, Soft, soft all valid)
8. WHEN the context text exceeds 500 characters, THE Command_Parser SHALL reject the command with a validation error

### Requirement 2: Group Chat Context Validation

**User Story:** As a bot admin, I want the `/roast` command to only work in registered group chats, so that the feature is used in appropriate contexts.

#### Acceptance Criteria

1. WHEN a user sends `/roast` in a private chat, THE TelegramRouter SHALL ignore the command (no response)
2. WHEN a user sends `/roast` in a group chat that is not registered with the bot, THE Bot SHALL respond with an error message indicating the group must be connected first
3. WHEN a user sends `/roast` in a registered group chat, THE TelegramRouter SHALL process the command

### Requirement 3: Input Validation

**User Story:** As a user, I want clear feedback when my command is invalid, so that I can correct my input.

#### Acceptance Criteria

1. WHEN a user sends `/roast` without a target username, THE Bot SHALL respond with usage instructions
2. WHEN a user sends `/roast @username invalidlevel`, THE Bot SHALL respond with an error listing valid levels (soft, hard, extra)
3. WHEN a user sends `/roast` with an invalid mention format, THE Bot SHALL respond with usage instructions
4. WHEN the context text exceeds 500 characters, THE Bot SHALL respond with an error indicating the maximum length

### Requirement 4: AI Roast Generation

**User Story:** As a group member, I want the bot to generate creative roasts using AI, so that I get unique and entertaining content.

#### Acceptance Criteria

1. WHEN a valid roast command is received, THE GenerateRoast_Use_Case SHALL construct a prompt with the target username, roast level, and optional context
2. THE GenerateRoast_Use_Case SHALL include level-specific instructions in the system prompt:
   - soft: Light and gentle teasing, wholesome humor
   - hard: Witty burns and clever insults, humorous but not mean-spirited
   - extra: Maximum roast energy, savage but still friendly
3. WHEN context is provided, THE GenerateRoast_Use_Case SHALL include it in the prompt to guide the roast content
4. WHEN no context is provided, THE GenerateRoast_Use_Case SHALL generate a generic roast based on the username only
5. THE GenerateRoast_Use_Case SHALL limit generated roasts to 2-3 sentences maximum

### Requirement 5: Language Handling

**User Story:** As a user, I want to provide context in my native language and receive roasts in that language, so that the humor is culturally relevant.

#### Acceptance Criteria

1. WHEN a user provides context in a specific language, THE AI_Provider SHALL generate the roast in the same language
2. THE system prompt SHALL instruct the AI to respond in the same language as the user's input
3. WHEN no context is provided, THE AI_Provider SHALL generate the roast in English by default

### Requirement 6: OpenRouter Integration

**User Story:** As a system, I want to integrate with OpenRouter API reliably, so that roast generation is consistent and performant.

#### Acceptance Criteria

1. THE OpenRouterClient SHALL send requests to the configured OpenRouter API endpoint
2. THE OpenRouterClient SHALL include the API key in request headers
3. THE OpenRouterClient SHALL use the configured model (default: openrouter/auto for automatic model selection)
4. THE OpenRouterClient SHALL set temperature to 0.8 for creative but coherent output
5. THE OpenRouterClient SHALL set max_tokens to 150 to limit response length
6. THE OpenRouterClient SHALL enforce a 5-second timeout on API requests
7. THE OpenRouterClient SHALL retry failed requests up to 2 times with exponential backoff

### Requirement 7: Response Handling

**User Story:** As a group member, I want to see the roast as a reply to my command, so that the context is clear to everyone.

#### Acceptance Criteria

1. WHEN the AI generates a roast successfully, THE Bot SHALL send the roast as a reply to the original command message
2. WHEN the AI request times out, THE Bot SHALL respond with a friendly timeout message
3. WHEN the AI rate limit is exceeded, THE Bot SHALL respond with a rate limit message
4. WHEN the AI response triggers content moderation, THE Bot SHALL respond with a moderation message
5. WHEN an unexpected error occurs, THE Bot SHALL respond with a generic error message

### Requirement 8: Rate Limiting

**User Story:** As a bot admin, I want to limit roast usage to prevent abuse and control API costs, so that the feature remains sustainable.

#### Acceptance Criteria

1. THE Rate_Limiter SHALL enforce a limit of 5 roasts per user per minute
2. THE Rate_Limiter SHALL enforce a limit of 20 roasts per group per minute
3. THE Rate_Limiter SHALL enforce a global limit of 100 roasts per minute
4. WHEN a rate limit is exceeded, THE Bot SHALL respond with a rate limit message indicating when the user can try again
5. THE Rate_Limiter SHALL use in-memory storage (with future Redis support planned)

### Requirement 9: Content Moderation

**User Story:** As a bot admin, I want the bot to filter inappropriate content, so that the feature remains fun and doesn't cause harm.

#### Acceptance Criteria

1. THE system prompt SHALL include guardrails instructing the AI to avoid offensive, discriminatory, or harmful content
2. WHEN the AI response contains blocked words or patterns, THE Bot SHALL replace the response with a moderation error message
3. THE Bot SHALL NOT send any PII to OpenRouter beyond Telegram usernames

### Requirement 10: Feature Toggle

**User Story:** As a group admin, I want to enable or disable the roast feature for my group, so that I can control what features are available.

#### Acceptance Criteria

1. WHEN a group admin sends `/settings roast off`, THE Bot SHALL disable the roast feature for that group
2. WHEN a group admin sends `/settings roast on`, THE Bot SHALL enable the roast feature for that group
3. WHEN the roast feature is disabled for a group, THE Bot SHALL respond with a message indicating the feature is disabled
4. THE roast feature SHALL be enabled by default for all registered groups

### Requirement 11: Configuration

**User Story:** As a system administrator, I want to configure AI parameters via config files, so that I can tune the feature without code changes.

#### Acceptance Criteria

1. THE configuration schema SHALL include OpenRouter settings (apiKey, baseUrl, defaultModel, timeout, maxRetries)
2. THE configuration schema SHALL include roast-specific settings (enabled, temperature, maxTokens, cooldownSeconds)
3. THE Bot SHALL validate configuration at startup using Zod schemas
4. IF required configuration is missing, THEN THE Bot SHALL fail to start with a clear error message

### Requirement 12: Help Menu Integration

**User Story:** As a user, I want to see the `/roast` command in the help menu, so that I can discover how to use it.

#### Acceptance Criteria

1. THE Command_Definition SHALL register metadata with the CommandRegistry
2. THE metadata SHALL include the command name `/roast`
3. THE metadata SHALL include a description explaining the command's purpose
4. THE metadata SHALL include usage examples showing the command format
5. THE metadata SHALL categorize the command under "Fun Commands"
6. THE metadata SHALL NOT mark the command as `privateOnly` since it works in groups
